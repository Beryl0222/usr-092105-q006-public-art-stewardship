# 公共艺术共创养护系统设计

把一次课程结项照片式的“一次性教学成果”，变成**从场地许可到最终拆除都可追责、可交接、可核对**的可持续管理系统。本文档说明角色、全生命周期、事件目录、关键不变量及其在《稻浪墙》剧情中的落点。

## 1. 要解决的问题

地铁通道公共艺术墙落成一年后开裂，暴露出一次性成果模式的结构性缺陷：

- 社区找学校、学校找施工方——**谁该修没有记录**；
- 旧打谷机被切割、改色，超出捐赠人原同意范围——**旧物按什么方式改造没有清单**；
- 结项照片能证明“做过”，回答不了**谁署名、传播谁说了算、课程结束后谁负责**；
- 课程结项、负责人调动后，未结维修随之“消失”。

系统的回答是：**把每个决定、每份同意、每次交接都记成不可删除的领域事件**，责任与资金由事件自动派生，案件只能靠“维修验收”或“正式拆除”关闭。

## 3. 全生命周期

```
场地许可 → 访谈/公众意见 → 意见汇总（仅调查记录）
  → 设计修订与取舍（设计方判断，理由留痕）
  → 参与者登记 · 旧物权属核实 · 旧物验收同意清单 · 影像/口述分别授权 · 署名定稿
  → 施工方案安全报备 → 施工日志（旧物改造不越界·未成年人专项安排）
  → 竣工验收（保修责任起算）→ 作品介绍页 · 授权化发布 · 巡检计划
  → 巡检 → 报损（自动带出责任人+资金）→ 派修 → 报价/拨付 → 完工 → 维修验收关闭
  → 课程结项/负责人调动：作品交接 + 未结案件随件移交（不关闭）
  → 重大改造：评审通过 → 作品新版本 → 新一轮施工与验收
  → 无法维修或许可终止：拆除提案 → 正式批准 → 实施 → 作品终结归档
```

## 4. 聚合与事件

原有四个公共聚合的事件语义保持稳定（`INPUT_COLLECTED` 在 site_agreement、`DESIGN_DECIDED` 在 design_revision、`MATERIAL_ACCEPTED` 在 contribution_record、`REPAIR_ASSIGNED`/报损在 maintenance_case），另增四类聚合承接全生命周期。完整字段必填项见 `contracts/event-catalog.json`。

- **artwork 作品主档**：`ARTWORK_REGISTERED`、`WORK_ACCEPTED`（沿用）、`ARTWORK_VERSION_OPENED`、`ARTWORK_HANDED_OVER`、`ARTWORK_INFO_PUBLISHED`、`ARTWORK_DECOMMISSION_APPROVED`、`ARTWORK_DECOMMISSIONED`。
- **site_agreement 场地与意见**：`SITE_PERMIT_REQUESTED/GRANTED/CLOSED`、`INPUT_COLLECTED`（沿用）、`PUBLIC_INPUT_SUMMARY_PUBLISHED`。
- **design_revision 设计**：`DESIGN_REVISION_PROPOSED`、`DESIGN_TRADEOFF_RECORDED`、`DESIGN_DECIDED`（沿用）、`DESIGN_CHANGE_REQUESTED/REVIEWED`。
- **contribution_record 贡献与授权**：参与者登记、协议签署、旧物 `MATERIAL_DONATION_OFFERED/OWNERSHIP_VERIFIED/ACCEPTED`（沿用）`/RECONSENTED/USE_RECONCILED`、`PARTICIPANT_AUTHORIZATION_GRANTED/WITHDRAWN`、`CREDIT_DECIDED`、`DISPUTE_FILED/RESOLVED`、`PUBLICATION_RELEASED`。
- **construction_project 施工安全**：方案报备、`SAFETY_FILING_APPROVED`、施工日志、安全事件、报验。
- **fund_agreement 资金**：约定（份额+每次上限）、拨付。
- **inspection_record 巡检**：计划、巡检记录。
- **maintenance_case 维修案件**：`DAMAGE_REPORTED`、`REPAIR_ASSIGNED`（沿用）、报价、拨付、完工、`REPAIR_ACCEPTED`、`CASE_OWNERSHIP_TRANSFERRED`、拆除提案/批准/完成。

## 5. 关键不变量（在 `src/policies.js` 强制）

1. **意见多少不替代设计判断。** `PUBLIC_INPUT_SUMMARY_PUBLISHED` 只记录调查；`DESIGN_TRADEOFF_RECORDED` 必须给出中选方案与理由，`DESIGN_DECIDED` 对采纳与不采纳的意见都要可追溯。剧情中发光字 61 票最高，仍因眩光与场地安全义务不中选。
2. **影像与口述记忆分别授权。** `subject_kind` 只能是 `image` 或 `oral_history`；撤回一类不影响另一类。
3. **未成年人授权必须有监护人同意。** 影像、口述两条授权分别附 `guardian_consent_id`。
4. **旧物先确权、再验收，改造方式以同意清单为界。** 未列入 `consented_transformations` 的做法视为未同意；超范围施工在日志环节即被拦截，必须有 `MATERIAL_RECONSENTED` 才能进行；事后争议以 `MATERIAL_USE_RECONCILED` 核对实际做法并给处置。
5. **重大改造形成新版本。** 只有评审通过的 `scope_class=major` 请求才能 `ARTWORK_VERSION_OPENED`（版本号严格 +1），施工方案的 `for_version` 必须等于作品当前版本；小修不开版本。
6. **施工安全前置。** 场地许可有效 + 安全报备获批且在有效期内才能记录进场；未成年人进场须有专项安排；高风险安全事件未关闭不得报验、不得竣工验收。
7. **署名必须回指本人已签署协议。** 任何署名条目没有本人协议即被拒绝；署名修订可取代旧版但旧版事件保留。
8. **传播逐条对授权。** 每个素材必须落在一条有效、未撤回、未过期且覆盖该渠道的授权范围内。
9. **争议裁定必须核对原始记录。** 署名争议核对协议，传播争议核对授权，旧物争议两者都查；无核对不得裁定。
10. **报损单自动带出责任与资金。** 立案时系统按发生时点的保修状态与交接链派生责任人，按生效中最新资金约定带出口径并冻结为快照；手工填写即拒绝。保修期内→施工方；过保→当前保管方。
11. **资金不超约定。** 每次案件累计拨付不得超过 `per_case_cap`；资金约定随交接持续有效并可更新版本。
12. **课程结束与人员调动不能弄丢案件。** `ARTWORK_HANDED_OVER` 必须列明当时**全部**未结案件（漏列即拒绝）；`CASE_OWNERSHIP_TRANSFERRED` 只换责任人，案件状态不变。
13. **案件只有两种合法关闭方式：** `REPAIR_ACCEPTED` 维修验收通过，或 `DEMOLITION_COMPLETED` 正式拆除完成。其余任何事件都不能关闭案件。
14. **拆除是正式链。** 有非拆除中的未结维修不得批准拆除；须先作品层 `ARTWORK_DECOMMISSION_APPROVED`（多方决定、构件去向），案件才能批准并实施，最后作品凭已关闭的拆除案件终结并归档。
15. **介绍页必须真实。** 宣称采用的旧物必须已验收，引用的访谈/意见必须存在；未采纳意见与理由一并公开。
16. **事件流级约定。** `event_id` 全局唯一（重试幂等沿用原标识），同一聚合 `version` 连续递增、发生时间不倒流。

## 6. 读模型（在 `src/projections.js`）

- `damageReportDraft`：报损单草稿——责任人与资金约定自动带出，报案人无需也不能手填。
- `artworkIntroPage`：作品介绍页——采用的在地记忆、旧物材料（含同意范围与核对结论）、未采纳意见及理由、署名。
- `authorizationCheck`：授权核对——按人/素材/发布回查协议、影像授权、口述授权、监护人同意、撤回状态。
- `openCasesBoard`：未结案件看板——跨课程学期、跨负责人调动，显示当前责任人、在册天数、超期情况。
- `materialTrail`：旧物全链路——捐赠意向→权属核实→验收同意清单→追加同意→实际使用→核对处置。
- `designTradeoffReport`：设计取舍说明——各选项支持度、中选项与理由。

## 8. 实现形态

- 事件溯源：`src/reducers.js` 纯函数归约当前状态；`src/policies.js` 在“追加事件前”的前缀状态上校验跨聚合不变量。
- 契约即数据：`contracts/event-catalog.json` 定义事件—聚合配对与载荷必填项，校验器、文档、测试共用，新增事件只需改目录。
- 无外部依赖，`node --test` 可跑全部 40 项测试（契约、完整剧情、19 条策略反例、读模型）。
